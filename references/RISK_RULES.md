# 域名检查与结论规则

## 风险结论（易读版）

| 结论 | 触发原则 | 给用户的建议 |
|---|---|---|
| 发现严重风险 | 有可靠、明确的高风险证据 | 不建议访问，先调查与处理 |
| 发现可疑问题 | 域名注册很新、域名或当前解析 IP 出现在名单、存在风险情报或异常跳转等线索 | 暂缓访问，逐条确认 |
| 信息不足 | DNS、有效本地名单或至少一个独立在线威胁情报源未成功获取，且未发现风险线索 | 补齐检测信息，再做判断 |
| 暂未发现明显风险 | 关键技术检查完成，且未触发明显风险线索 | 可谨慎访问，不代表绝对安全 |

## 证据如何处理

- 名单精确命中目标域名，比共享 CDN/IP 关联更有解释力；两者不能混为一谈。
- OTX Pulse、历史网站跳转、来自其他来源的转载情报不能直接等同于已确认恶意。
- 没有匹配、请求失败、API 未配置、缓存已过期是四种不同情况。
- RDAP 注册时间长不代表安全；网站可用也不代表安全；证书存在不代表 HTTPS 当前正确。
- 未获得真实供应商和内容证据时，不推断网站背后的实际运营主体。
- 检查时间与证据首次/末次观察时间分开记录；历史证据不作为实时状态证明。
- 风险结论是自动化技术建议，不会直接修改 DNS、代理、防火墙或浏览器设置。

## HTML 与 JSON

HTML 顶部明确显示建议，并突出问题、正常完成的项目和未完成的项目。技术详情折叠。JSON 保留原始查询状态、来源链接与时间。所有动态 HTML 文本必须进行转义，不引入外部脚本资源。
