# 外联域名安全评估规则 / 审计要点

## 1. 威胁风险 vs 业务准入：必须分开

**威胁风险证据**回答“这个域名是否存在可见的可疑迹象”。

**业务准入审查**回答“这个内网系统以指定方法连接外部服务，能否满足单位网络/数据保护要求”。前者低风险不足以推导后者可以放行。

四个审查轴：注册身份、技术基础设施、业务数据流向、网络出口最小权限与审计。每个审查轴需明确「证据 / 缺失 / 风险 / 待办」。

## 2. 自动化规则（v1.4）

| 情形 | 解释 | 处理 |
| --- | --- | --- |
| 域龄 <30 天 | 新注册域名，但不必然恶意 | 中风险信号；核实域名归属、合同和业务必要性 |
| 域龄 30–89 天 | 年轻域名 | 低风险关注项 |
| VirusTotal 返回恶意/可疑检测（仅明确合规非商业模式） | 恶意/可疑计数是线索，不等于已确认恶意 | 中风险信号，核验引擎结果、分析日期与误报 |
| VirusTotal 因商业限制被跳过 | 属于合规控制而非情报负面/正面证据 | 标记 `skipped` 与 `commercial_use_restriction`；不得解释为 0 命中；补充合规情报复核 |
| 国内情报网页人工记录 malicious/suspicious | 必须精确 FQDN，留审核人/日期/截图或工单证据；不同平台可能共享同源 IOC | 中风险信号 + 人工复核，不能仅凭命中数自动高风险或拒绝；原始证据确认后按制度处理 |
| 国内平台未查到/人工标记 no_known_threat | 平台覆盖有限，数据与查询时效不同 | 仅表明未观察到已知恶意，不构成低风险或安全保证 |
| 微步域名分析 API 未授权/没有确认免费额度 | 免费 X 网页账户不等于拥有免费域名分析 API | 跳过 API，不当作零命中；按真实网页证据复核 |
| 微步原生未过期恶意类别情报 | 来源和类型待复核 | 中风险线索；其 `open_source` 转载不得与 OTX 重复计算 |
| PhishShield 本地名单精确 FQDN 命中且缓存 7 天内更新 | 仅为钓鱼候选 IOC；数据抓取时间不等于威胁首次/最后出现时间 | 中风险待复核线索，核实上游原始案例、误报和当前存活情况 |
| IPGuard 本地规则命中当前解析公网 IP | 共享云 / CDN IP 可能与攻击来源共用基础设施 | 中风险提示、**低可信关联**，必须人工核实，不能据此认定域名恶意 |
| anti-AD 本地规则精确命中 | 广告/追踪/隐私名单，不是恶意威胁情报 | 仅低风险背景信号；不可直接判断站点恶意或自动封禁 |
| 本地 IOC 规则未建立/超过 7 天 | 不掌握可靠的新鲜 IOC 快照 | 标注待更新，不能作为“安全”阴性证据 |
| OTX 有关联 Pulse | 可能是历史关联、误报或社区线索 | 中风险信号，人工核实脉冲内容、日期、IOC 相关性 |
| urlscan 已有记录发生 off-domain 跳转 | 可能是 CDN/认证/正常跳转 | 中风险信号，业务方确认真实目标是否一并授权 |
| 公网 FQDN 解析到私网/不可全局路由 IP | 可能是 split-horizon、CDN/解析策略或异常 | 中风险信号；先排查解析视图与目标地址 |
| 经授权的 TLS 探测错误 | 可能是证书、网络阻断、端口问题 | 中风险信号；不能直接认为恶意 |
| RDAP/DNS/外部数据源查询失败 | 没有证据，不是清白证明 | “待补充”而不是 0 风险 |
| 来源未注册/Key 不可用 | 可缺省执行，不是假阴性 | 标注 `not_configured` 或 `error` |
| 业务方上传数据或传输敏感信息 | 需要独立数据安全/供应商审批 | 中风险信号 + 待审批 |
| 业务方明确标识存在已核实恶意证据且提供 `confirmed_malicious_evidence_reference` | 需要更高安全级别审查 | 高风险，默认不放通；**字段须由人工负责确认** |

## 3. 必要的业务审批材料

1. 访问源系统和责任人，准确目标 FQDN、协议端口；源地址列表应在**受控工单**里交付而非第三方查询平台。
2. 供应商名称、合同/服务文档、域名归属证明，确认 FQDN（包括 CNAME/跨域重定向）确由供应商控制。
3. 数据分类、请求方向/频率、是否包含客户信息或内部敏感日志、凭据和文件。
4. 出口代理/网关、域名和端口白名单、日志留存、告警、变更回收和重新评审机制。
5. 业务、安全、数据合规审批状态；异常时由安全专员分析确认。

## 4. 结论必须是可审计的，而非“分数幻觉”

- **高风险（经人工明确确认恶意）**：不建议放通，升级安全审查。
- **存在中等风险信号**：暂缓放通，人工确认风险真实程度与控制措施。
- **资料不足**：暂缓放通，补充来源数据、域名归属、用途和数据流向。
- **无触发且材料齐全**：仅能表达“可以进入人工准入审批”；不能直接在防火墙放通。

脚本没有商业供应商 Risk Score，也不会生成缺乏依据的 0–100 分数。

## 5. 人工安全专家的补充动作

- 对注册人、注册商、历史运营公司进行交叉核验。
- 检查威胁情报原始证据是否与目标 FQDN 强关联，区分 CDN/共享 IP 的间接关联。
- 检查 HTTP/HTTPS 实际访问行为与数据的必要性，验证前置代理是否控制 HTTP CONNECT/SNI/目标证书/域名范围；在受控测试环境进行。
- 对 SaaS/API 服务判断外包/隐私/数据出境和客户数据存储问题。
- 如 DNS 解析动态变化，应在出口侧实施域名绑定或代理控制，避免仅使用一次性解析 IP 白名单。

## 6. 标准化字段与可复用数据

- `report_id`, `checked_at`, `domain`, `registered_domain`, `vt_usage`
- `business_context`
- `sources`: `rdap`, `dns`, `ripestat`, `crtsh`, `otx`, `urlscan`, `virustotal`, `tls`, `threatbook_api`, `threatbook_x_manual`, `qianxin_ti_manual`, `tencent_tix_manual`, `local_ioc`
- 每个来源：`status`, `checked_at`, `summary`, `data`, `error`, `source_url`
- `assessment`: `risk_label`, `decision`, `findings`, `pending_items`, `automatic_approval`（永远 `false`）

建议在 ITSM 流程引用报告编号并留存 JSON + 签审版 Markdown/PDF，以便半年/一年后按相同 FQDN 重新核查发生的变化。

## 7. 补充：证据来源、历史时效、被动依赖与对比

- 每个成功/失败/空/未配置/跳过的数据源都保留单独 `checked_at`，不能把本次查询时间误写成第三方记录生成时间；`observed_at` 只有真实第三方原始时间时才填写。
- `evidence_ledger` 的证据编号在一次报告内稳定：`EV-01` RDAP，`EV-02` DNS，`EV-03` RIPEstat，`EV-04` crt.sh，`EV-05` OTX，`EV-06` urlscan，`EV-07` VirusTotal，`EV-08` TLS；编号仅在这一结构内有效，跨报告依赖报告 ID。
- `confidence` 是**线索/归属强度**，不是安全评级。单一社区 Pulse 属低可信度关联证据，不等于恶意；观察到 DNS CNAME 也不能证明所有权。
- `asset_inventory` 中只有 `in_approved_scope=true` 的申请 FQDN 在当前审批范围。历史跳转、CNAME 和外部 CDN 是被动观察结果，必须另行确认批准范围，禁止自动向它们发送新的扫描请求。
- `evidence_coverage` 中非 `ok` 的来源表示信息覆盖不完整，`empty` 只是无记录，不是安全。
- 历史扫描/分析的 `observed_at` 超过 90 天应突出时效风险。90 天是**本工具自定义提示阈值**，不是安全行业或监管标准。
- `--baseline` 检测本次与上次报告的 IP、CNAME、注册商变化。变更可能是 CDN 调度、扩容、注册商迁移等正常原因，必须复核，不得根据变化直接判定恶意。只有两次数据源均有效才比较该字段。
- 跨报告长期监控应基于合法使用与外联许可，建议在内网人工审核后留存快照；不要将业务上下文发往第三方情报平台。

### 报告 v1.2 核心机器字段

`schema_version`，`evidence_ledger[]`，`evidence_coverage`，`asset_inventory[]`，`baseline_comparison`（可选），以及原有 `sources` / `assessment`。风险发现的可选字段 `evidence_ids`、`confidence` 便于审计回溯。

## 8. 国内情报矩阵（v1.3）

- `domestic_cross_validation.matrix[]` 为每个厂商记录状态、判断、人工核查时间和证据引用；`manual_checked_count` 是证据覆盖数量，**不是安全票数**。
- 只评估申请 FQDN；同 IP、同注册域、相关恶意子域只作调查线索，不得移花接木。
- 明确命中恶意/可疑仅作为中风险信号；要求安全分析师结合原始网页/关联样本/时间/误报核实。高风险只有经授权人工确认恶意证据后触发。
- 免费服务商业条款、查询字段及配额随时可能调整；默认手工查询、微步 API 默认禁用，严禁绕开 API 门槛抓取网页。

## 9. 中国开源本地 IOC（v1.4）

- `sources.local_ioc.data.feeds[]` 保存规则来源、许可证、SHA256、下载时间、是否过期和来源组。`matched[]` 保留精确匹配或 IP 弱关联及原始注释。
- `domestic_cross_validation.matrix[]` 增加 `mode=offline_feed`，但是**不计入不同国内商业厂商人工核查的覆盖数量**。
- 本地 IOC 只在管理员执行 `ioc-update` 时联网下载公开数据，`audit` 对 IOC 本地库只读。超过七天算缓存过期，下载时间不是 IOC 观测时间。
- 不自动拉取广告拦截表，除非机构已核实上游聚合许可证后明确启用 `--include-adtracking --license-reviewed`。
- 免费开源源均不得作为唯一准入依据。见 `references/LOCAL_IOC.md`。
